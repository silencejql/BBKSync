## 简介

BBK 文件同步与备份工具（程序名 **BBKSync**）是一款局域网内的 BBK 文件夹备份、同步与远程运维工具。
它基于 TCP 直连通信，两端各运行一个本程序即可互传文件、备份 BBK、管理进程；
也支持免安装对端，通过 Windows 共享（SMB）完成备份与更新。

**典型组网：**

```
        ┌─────────────────────┐   TCP 25010（可改）  ┌─────────────────────┐
        │  本机 BBKSync       │ ◄──────────────────► │  远端 BBKSync       │
        │  （主动操作方）      │                      │  （启动服务即可）    │
        └─────────┬───────────┘                     └─────────────────────┘
                  │ SMB（c$ / 共享名）
                  ▼
        ┌─────────────────────┐
        │  Windows 共享主机    │  无需安装本程序
        └─────────────────────┘
```

**主要功能：**

- **BBK 备份** — 备份本机、多台局域网远端或 Windows 共享上的 BBK 文件夹，自动按设备号/产线号命名
- **BBK 更新** — 在电脑之间同步 BBK 文件夹（接收 / 推送 / 共享更新），增量比对、Bin 可整体替换、更新前自动备份
- **文件同步** — 任意文件或文件夹的双向同步（同步给远端 / 从远端同步），支持更新模式与拷贝模式
- **进程管理** — 远程启动、关闭远端电脑上的应用程序，可在线获取远端文件列表
- **程序升级** — 把本机 BBKSync.exe 推送到一台或多台远端并自动替换重启
- **其他小工具** — 备份整理：递归剔除同名旧备份、批量删除备份名称中的日期段，删除项均进回收站可还原
- **Windows 共享支持** — 对端无需安装程序，通过 SMB 共享备份/更新
- **亮色 / 暗色主题** — 一键切换，全部窗口统一风格

## 功能特性

- 单文件自包含发布（win-x64），**无需安装 .NET 运行时**，双击即用
- 单实例运行（互斥体 `BBKSync_SingleInstance`），防止重复启动
- 批量 IP 处理：一次输入多台电脑，逐台执行并汇总成功/失败
- 灵活的 IP 简写：支持 `192.168.1.5-8`、`192.168.1.1,5,7`、`192.168.1.1-3,6-8` 等
- 本机地址自动识别与跳过，避免把本机误当远端操作
- 文件按「大小 + 修改时间（1 秒容差）」增量比对，相同文件不重复传输
- 传输先写临时文件再原子替换，失败自动重试，不破坏原文件
- 更新类操作前自动备份原文件/文件夹，命名带日期可追溯
- BBK 更新、文件同步、进程管理标签页支持密码保护；解锁后 **5 分钟无任何键盘/鼠标操作自动重新上锁**（操作执行期间不计入空闲）
- 备份整理小工具递归扫描全部子文件夹，按备份名称中的日期分组保留最新；删除项一律移入回收站可还原
- 开机自启并驻留托盘，适合产线电脑常驻监听
- 崩溃自动写 `crash.log`，界面异常可追溯

## 安装与启动

### 运行环境

- **Windows 10 1607 及以上 / Windows 11**（x64；.NET 10 自包含运行时的系统要求）
- 无需安装任何运行时或依赖
- 以当前用户权限（asInvoker）运行，**不需要管理员身份**
- 建议放在**纯英文路径**下使用，可避免个别安全软件对中文路径的拦截

### 启动方式

1. 直接双击 `BBKSync.exe` 运行。
2. 程序启动后会**自动尝试启动本机服务**（端口被占用时静默跳过，可手动启动）。
3. 首次运行在程序同目录自动生成：
   - `settings.json` — 全部设置
   - `Update_BBKSync.bat` — 程序升级时远端执行的替换脚本
   - `PostgreSQL_Backup.bat` — 备份前数据库脚本模板（已有内容时不会覆盖）
4. 如果程序目录没有写入权限，配置与历史文件改存到 `%LocalAppData%\BBKFileSync\`。
5. 同时只能运行一个实例，重复启动会提示「BBKSync 已在运行中」。

## 通用操作约定

### 1. 勾选框必须双击切换

界面上**所有勾选框（CheckBox）都通过双击切换**勾选状态（勾选 → 取消，未勾选 → 勾选）；
单击被刻意阻止，避免误触。

### 2. 本机地址自动跳过

BBK更新、文件同步、程序升级等远端操作执行前，会自动判断目标 IP 是否为本机
（回环 `127.0.0.1`、`::1`、`localhost`，以及本机所有网卡 IPv4 和主机名地址）：

- 部分为本机：弹窗列出被跳过的本机 IP，对其余远端继续执行；
- 全部为本机：提示并中止本次操作。

### 3. 多台电脑依次处理

IP/范围解析出多台电脑时，操作**逐台串行执行**：每台独立记录成功/失败，
单台失败不影响其余电脑，全部结束后弹窗汇总失败清单。
成功连接过的原始输入会保存到历史记录。

### 4. 统一的校验提示

- IP 为空：「请输入远端 IP 或范围。」
- 端口无效（非 1~65535）：「远端端口无效。」
- 文件同步路径为空：「请先选择/输入要同步的远端文件或文件夹路径。」

### 5. 忙时锁定与取消

操作执行期间，相关输入与按钮自动禁用，仅「取消」可用；点击「取消」可中止正在进行的批量操作。

## 本机配置

| 设置项 | 说明 | 默认值 |
|--------|------|--------|
| **BBK 文件夹** | 本机 BBK 根目录，备份/同步以此为源或目标 | `D:\BBK` |
| **端口** | 本机 TCP 服务监听端口（1~65535） | `25010` |
| **启动服务** | 开始监听，等待远端连接 | — |
| **停止服务** | 停止监听 | — |
| **开机自启并后台监听（驻留托盘）** | 写入注册表开机启动，启动后驻留托盘 | 关闭 |

点击「启动服务」后，状态栏右侧显示本机全部局域网 IPv4 地址，供其他电脑填写。
程序每次启动也会自动尝试启动服务（无弹窗，失败仅写日志）。

## 远端电脑配置

| 设置项 | 说明 |
|--------|------|
| **IP/范围** | 可输入单台 IP、多台 IP 或范围；也可下拉选择历史记录/IP 配置 |
| **远端端口** | 远端服务监听端口，默认与本机端口相同 |
| **测试连接** | 对所有解析出的 IP 逐一验证 TCP 连通性与协议应答 |
| **历史** | 管理连接历史与备注 |
| **IP 配置** | 维护 IP 与电脑名称的映射 |

### IP 输入格式

分隔符支持英文/中文逗号（`,` `，`）、英文/中文分号（`;` `；`）、空格、制表符与换行，可任意混用。

| 格式 | 示例 | 解析结果 |
|------|------|----------|
| 单个 IP | `192.168.1.5` | `.5` |
| 逗号分隔 | `192.168.1.5,192.168.1.8` | `.5`、`.8` |
| **纯数字继承前缀** | `192.168.1.1,5,7` | `.1`、`.5`、`.7` |
| 末段短范围 | `192.168.1.5-8` | `.5`、`.6`、`.7`、`.8` |
| **混合简写范围** | `192.168.1.1-3,6-8` | `.1`、`.2`、`.3`、`.6`、`.7`、`.8` |
| 完整范围 | `192.168.1.5-192.168.1.8` | `.5` ~ `.8` |

规则与限制：

- 末段取值范围 **1~254**（0 与 255 不允许）；
- 范围起止必须在同一网段，且起始不能大于结束；
- 历史记录与下拉框保存的是**原始输入字符串**（如 `192.168.1.1-3,6-8`），不是展开后的单个 IP。

### 测试连接

对每个 IP 执行两步检测（**每步超时 1 秒**）：

1. **TCP 连通性**：能否建立连接；
2. **协议应答**：发送探测握手，验证对端确实运行着 BBKSync，并读回远端设备号/产线号。

结果逐行写入日志（「[成功]」普通色 /「[失败]」红色），结束后弹窗汇总。常见错误：

| 提示 | 含义 | 建议 |
|------|------|------|
| 10060 超时 | 远端不可达或防火墙静默丢包 | 检查 IP、网络与防火墙 |
| 10061 积极拒绝 | 端口未监听，远端未启动服务 | 在远端点「启动服务」 |
| 10013 权限访问 | 本机安全软件/防火墙拦截 | 改放纯英文目录、放行防火墙 |
| 已连上但无协议应答 | 服务僵死、端口被其他程序占用、对端不是本程序 | 重启远端程序或核对端口 |

> 正式备份/同步等操作的 TCP 连接阶段使用 **5 秒连接超时**；测试连接为快速巡检，使用 1 秒。

## BBK 备份

### 备份来源（三选一）

| 选项 | 说明 | 对端要求 |
|------|------|----------|
| **本机** | 备份本机 BBK 文件夹 | — |
| **局域网电脑（可多台）** | 从远端逐台拉取 BBK 备份，支持多台 | 远端启动服务 |
| **Windows 共享** | 通过 SMB 共享备份 | 仅需开放共享 |

### 备份目标与命名

备份存放在「备份到」父目录下，自动建立如下结构：

```
备份目录\
  └─ Line<产线号>\            ← 仅当检测到 LineNo 时
       └─ BBK_<设备号>_yyyyMMdd\
            ├─ Bin\
            ├─ Config\
            └─ ...
```

- 设备号（DeviceNo）与产线号（LineNo）自动从 BBK 子目录的 `Config\SystemConfig.xml`
  的 `<Other><KeyName>` 中解析，取**修改时间最新**的一份（Bin 开头的目录不参与查找）；
- 读取不到设备号时，回退使用「IP 配置」中的电脑名称或 IP；
- 备份目标**不能等于源目录，也不能位于源目录内部**，否则会直接报错。

### 备份选项

| 选项 | 说明 | 默认 |
|------|------|------|
| **Log 文件夹只备份最近 N 天** | 路径任一段含 `Log` 的文件，仅备份最近 N 天（按修改时间） | 开启，2 天 |
| **自动获取设备配置** | 自动解析 DeviceNo / LineNo 用于命名与分产线目录 | 开启 |
| **备份完成后自动压缩为 zip（删除文件夹）** | 打包为同名 `.zip` 后删除原文件夹 | 开启 |
| **备份前先执行 PostgreSQL 备份脚本** | 备份前先执行 `PostgreSQL_Backup.bat`；局域网备份时脚本在**远端执行**，完成后再拉取 | 关闭 |
| **启用忽略规则（正则表达式）** | 关闭后忽略规则不生效，备份全部文件 | 开启 |

### 忽略规则

- 每行一条正则，也可用逗号分隔；大小写不敏感；
- 匹配对象是**相对 BBK 根目录的路径**，路径分隔符统一为 `/`（如 `Bin/app.exe`）；
- 非法正则自动忽略，不会中断备份。

常用示例：

| 正则 | 说明 |
|------|------|
| `\.bak$` | 忽略所有 `.bak` 文件 |
| `副本` | 忽略路径含「副本」的内容（默认规则为 `副本|copy|-`） |
| `(^|/)\.git(/|$)` | 忽略任意位置的 `.git` 文件夹 |
| `(^|/)Temp(/|$)` | 忽略顶层 Temp 文件夹 |

> 注意：这是正则，`*` 要写成 `.*`；程序自身产生的 `.tmp` 临时文件始终自动跳过。

### PostgreSQL 备份脚本

勾选「备份前先执行 PostgreSQL 备份脚本」后，程序在程序目录寻找 `PostgreSQL_Backup.bat`
并执行其内容；脚本不存在或为空时跳过（首次运行会生成默认模板，默认调用
`pg_dump` 备份 `LocalDB` 到 `D:\BBK\DataBase`，可按需修改，**程序不会覆盖已有内容**）。
脚本失败只记录警告，备份仍会继续。

## BBK 更新

> **密码保护：** 首次进入本标签页需输入密码（密码框右侧眼睛图标可显示/隐藏，回车可确认）。
> 密码取自 `settings.json` 的 `UpdatePassword`（**默认 `BBK123`**），留空则不启用。
> 切换到其他标签页后自动重新加锁；**停留在已解锁页面连续 5 分钟无键盘/鼠标操作也会自动重新上锁**
> （备份/更新等操作执行期间不计入空闲，操作结束后重新计时）。

### 更新方向

| 选项 | 含义 | 规则以哪侧为准 | 多台支持 |
|------|------|----------------|----------|
| **接收远端更新（远端为源）** | 从远端拉取 BBK 更新本机 | 本机界面规则 | 仅允许 1 个 IP |
| **推送本机到远端（本机为源）** | 把本机 BBK 推送到远端 | **远端界面规则** | 可多台 |
| **从共享文件夹更新本机（免安装）** | 从 SMB 共享读取并更新本机 | 本机界面规则 | — |

### 内置跳过目录

BBK 更新**自动跳过 `Log` 文件夹，以及 Bin 之外的 `Config` 文件夹**
（即各产线配置与日志不会被覆盖；Bin 内文件不受此限）。

### 更新规则

| 选项 | 说明 | 默认 |
|------|------|------|
| **Bin 整体替换（不勾则按日期增量）** | 勾选后先删除本机 `Bin` 再整体拷贝；不勾按大小/修改时间增量同步 | 关闭 |
| **同步前先备份被更新电脑的 BBK** | 更新前把被更新侧 BBK 备份到「备份到」目录下的 `BBK_AutoBackup_yyyyMMdd` | 开启 |
| **备份完成后自动压缩为 zip（删除文件夹）** | 同步前备份完成后打包压缩 | 开启 |

增量判定：本地不存在、大小不同，或修改时间相差超过 **1 秒** 即需要更新。

### 同步流程

```
1. 连接对端并发送/接收文件清单（路径、大小、修改时间）
2. 按规则计算需要更新的文件列表（少于 10 个时会逐条打印）
3. 如启用同步前备份：先备份被更新侧 BBK，必要时压缩
4. 源端逐个发送文件，目标端先写 .tmp 临时文件再原子替换
5. 汇总失败/跳过项，完成
```

推送时，远端在备份阶段产生的日志会**实时回传**到本机日志区（前缀「[远端备份]」）。

## 文件同步

> **密码保护：** 本标签页与 BBK更新共用 `UpdatePassword` 密码，进入时需解锁；
> 切走或解锁后连续 5 分钟无操作会自动重新加锁。

把任意文件或文件夹按**相同绝对路径**在两台电脑间同步。两个方向共用同一个路径输入框：

- **同步给远端**：路径为本机源文件/文件夹；
- **从远端同步**：路径为要拉取的远端文件/文件夹（远端路径）。

### 两种模式（由「是否更新文件」勾选控制）

| 模式 | 行为 | 「相同则跳过」 |
|------|------|----------------|
| **更新模式**（勾选，默认） | 先把目标侧原文件/文件夹备份重命名，再覆盖到原路径 | 可同时勾选：大小与修改时间都相同则跳过 |
| **拷贝模式**（取消勾选） | **不改动原文件**，同步过来的内容以带设备信息的新名字另存 | 不适用（拷贝模式总是全量保存） |

### 命名规则（日期均为 `yyyyMMdd`）

| 方向 | 模式 | 原文件去向 | 新内容位置 |
|------|------|------------|------------|
| 同步给远端 | 更新 | 远端原文件重命名为 `名称_AutoBackup_日期.ext`；原文件夹复制备份为 `名称_AutoBackup_日期` | 覆盖到相同路径 |
| 同步给远端 | 拷贝 | 不动 | 单文件：同目录 `名称_AutoUpdateFrom_本机设备_日期.ext`；文件夹：同目录 `文件夹_AutoUpdateFrom_本机设备_日期` |
| 从远端同步 | 更新 | 本地原文件/文件夹重命名为 `名称_AutoBackup_日期` | 拉取到原路径 |
| 从远端同步 | 拷贝 | 不动 | 单文件：同目录 `名称_AutoUpdateFrom_远端设备_日期.ext`；文件夹：同目录 `文件夹_AutoUpdateFrom_远端设备_日期` |

- 设备信息取 BBK 的 DeviceNo，取不到则用电脑名；同名备份再次生成时会自动加序号避免覆盖；
- 远端路径不存在时，远端会返回错误并跳过该路径；
- 同步前有确认弹窗，明确列出方向、目标、内容与模式说明。

## 进程管理

> 本标签页与 BBK更新共用 `UpdatePassword` 密码，进入时需解锁；切走或解锁后连续 5 分钟无操作会自动重新加锁。

在远端电脑上远程启动或关闭应用程序（典型用途：FreeFormsAlways 产线程序）。
远端需先启动 BBKSync 服务。

### 启动远端应用程序（左列）

| 设置项 | 说明 |
|--------|------|
| **程序路径** | 要在远端启动的完整路径，可手填、本机「浏览...」选择 exe，或从远端文件列表下拉选择 |
| **文件后缀** | 匹配关键字，默认 `xmlFreeForm`，可切换 `exe`；多个用逗号/分号分隔 |
| **获取文件列表** | 递归列出远端 `D:\BBK` 下名称或扩展名匹配关键字的文件，去重排序后填入路径下拉框 |

点击「启动远端应用程序」后，远端以资源管理器双击方式（ShellExecute）启动该路径；
启动按钮有 **5 秒防连点冷却**。返回信息包含远端当前同名进程数量。

### 关闭远端应用程序（右列）

| 设置项 | 说明 |
|--------|------|
| **关闭进程前缀** | 进程名前缀，默认 `FreeFormsAlways`，可切换 `DataBaseQuery`；多个用逗号/分号分隔 |

远端按前缀匹配进程名（不区分大小写），结束整个进程树；
5 秒内未退出时回退用 `taskkill /PID xxx /T /F` 强制结束，
并回报「已关闭 / 剩余 N 个同类进程 / 未找到或已关闭」。

## 程序升级

把**本机当前正在运行的 BBKSync.exe** 推送到一台或多台远端电脑并自动替换重启。
在「程序升级」标签页点击下方「程序升级」按钮（或切到该页后按钮自动启用）。

执行前同样会做本机 IP 过滤，并要求二次确认。远端流程：

```
1. 本机连接远端（角色 update），远端回复就绪
2. 本机把当前 exe 原样发送给远端，存为 BBKSync_New.exe
3. 远端断开连接，1 秒后静默执行 Update_BBKSync.bat：
   等待 3 秒 → taskkill 结束旧程序 → 等待 2 秒
   → 删除旧 exe → 把 BBKSync_New.exe 改名为 BBKSync.exe
   → 以 --minimized 参数重新启动
```

注意事项：

- `Update_BBKSync.bat` 在每次程序启动时按当前目录与 exe 名**自动重新生成**，无需手动维护；
- 升级期间远端服务短暂中断（约 5 秒），完成后自动以最小化方式重启并继续服务；
- 确保两端架构一致（均为 x64）；
- 建议升级前先停止远端正在进行的 BBK 操作。

## 其他小工具（备份整理）

「其他小工具」标签页内含「备份整理」子页，子页顶部选择待整理文件夹，
下方两个功能页签（功能说明也可悬停页签查看 ToolTip）：

- 共用的「文件夹」选择框：待整理的备份根目录，留空时默认使用「备份到」目录；
- **递归扫描全部子文件夹**（带日期命名的备份文件夹视为整体，不再深入；自动跳过 junction 防止循环），
  按备份**所在的文件夹分别分组**，列表名称列显示相对路径（如 `PC1\BBK_20260901.zip`）；
- 识别对象：名称结尾带日期段的文件夹或 `.zip` / `.rar` / `.7z` 压缩包，
  日期格式支持 `yyyyMMdd`（`BBK_AutoBackup_20260918`）与 `yyyy-MM-dd`（`BBK_PC1_2026-09-10`）；
- 列表按相对路径排序（同组相邻），**不按操作排序**，便于对比每组保留/删除了哪个；
- 所有删除/替换下来的旧项目一律**移入回收站**，可随时还原。

### 剔除旧备份文件

同一文件夹内、去掉日期段后名称相同的备份视为一组，**每组只保留名称中日期最新的一个**，
其余在「扫描预览」中标记为「删除」：

1. 选择文件夹后点「扫描预览」，列表列出全部备份及操作（保留 / 删除）与名称日期，底部显示汇总；
2. 确认无误后点「执行删除」，弹窗二次确认，删除项移入回收站。

> 取舍只依据**名称中的日期**，与文件修改时间无关。

### 删除日期命名

在剔除旧备份的基础上，进一步把保留项名称结尾的「_日期」段去掉：

- 目标名称不存在：组内名称日期最新的一项执行**重命名**（如 `BBK_PC1_20260918.zip → BBK_PC1.zip`），
  其余旧项移入回收站；
- **目标名称已存在（按文件修改日期取舍）**：
  - 候选项的修改日期**新于**已有目标 → 候选项重命名替换，旧目标移入回收站（执行前会再次核验日期）；
  - 已有目标的修改日期**不早于**候选 → 保留目标，候选标记「跳过」，组内旧项仍删除。

不同子文件夹内的同名备份各自独立分组、独立重命名，互不冲突。
确认弹窗会明示重命名数量，以及其中「替换旧目标」的数量。

```json
{
  "Version": 2,
  "Server": {
    "Root": "D:\\BBK",
    "Port": 25010,
    "AutoStartAndListen": false
  },
  "Backup": {

  "UpdatePassword": "BBK123"

```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `Version` | int | 配置格式版本，用于自动迁移，勿手动修改 |
| `Server.Root` | string | BBK 根目录 |
| `Server.Port` | int | 监听 / 默认远端端口 |
| `Server.AutoStartAndListen` | bool | 开机自启并驻留托盘 |
| `Backup.Dest` | string | 备份目标父目录 |
| `Backup.BeforeSync` | bool | BBK 更新前先备份被更新侧 |
| `Backup.LogRule` | bool | 启用 Log 保留天数规则 |
| `Backup.LogDays` | int | Log 保留天数 |
| `Backup.IgnoreRegexEnabled` | bool | 启用忽略正则 |

## 开发者指南（构建 / 发布 / 项目结构）

### 环境要求

- [.NET 10 SDK](https://dotnet.microsoft.com/download)（项目目标框架 `net10.0-windows`）
- Windows + Visual Studio 2022 / Rider / VS Code 均可，或直接使用 `dotnet` CLI

### 常用命令

```powershell
# 调试构建
dotnet build .\LanFileSync\LanFileSync.csproj

# 发布单文件自包含版本（csproj 已内置 win-x64 / SingleFile / 压缩等参数）
dotnet publish .\LanFileSync\LanFileSync.csproj -c Release -o .\publish

# 可选：整理发布目录，把运行时文件移入 deps 子目录并删除 pdb
.\reorganize_publish.ps1
```

发布产物核心为单个 `BBKSync.exe`（约 70 MB，首次运行后在同目录生成 json/bat 等附属文件）。

### 版本号与 git tag（MinVer）

项目引用 [MinVer](https://github.com/adamralph/minver) 8.0.0，`MinVerTagPrefix` 为 `v`，
版本号完全由 git 历史决定，**无需手工改版本**：

- 在正式 tag 上构建：tag `v1.3.5` → 版本 `1.3.5.0`，标题显示 `v1.3.5`；
- tag 之后的提交：自动得到 `1.3.6-alpha.0.<提交数>`，产品版本附带 commit 哈希；
- csproj 中的 `UseFullTagAssemblyVersion` target 把 AssemblyVersion 也对齐为
  `major.minor.patch.0`，因此窗口标题（读取程序集版本）与文件版本保持一致。

发布正式版流程（手动）：

```powershell
git tag v1.4.0
dotnet publish .\LanFileSync\LanFileSync.csproj -c Release -o .\publish
git push origin v1.4.0
```

### 一键发版脚本 release.ps1

仓库根目录提供 [release.ps1](release.ps1)（兼容 Windows PowerShell 5.1+，文件为带 BOM 的 UTF-8），
自动完成「校验 → 打 tag → 发布 → 校验产物版本 → 可选整理目录 → 可选推送」全过程。
关键顺序是**先打 tag 再发布**（MinVer 依据 tag 计算正式版本）；
任何步骤失败都会自动删除本次新建的本地 tag，修正后可直接重跑。

前置条件：工作区干净（无未提交改动）、已安装 .NET 10 SDK、本地与远端不存在同名 tag。

```powershell
# 本地发版（打 v1.4.0，发布到 .\publish，不推送）
.\release.ps1 -Version 1.4.0

# 发版并推送分支与 tag 到 GitHub
.\release.ps1 -Version 1.4.0 -Push

# 预发布版本（产品版本为 1.4.0-beta.1+commit）
.\release.ps1 -Version 1.4.0-beta.1 -Push

# 清空 publish 后发布，并运行 reorganize_publish.ps1 整理运行时目录
.\release.ps1 -Version 1.4.0 -CleanPublish -Reorganize
```

| 参数 | 作用 | 默认 |
|------|------|------|
| `-Version` | **必填**，不带 `v` 前缀的版本号，支持预发布后缀（如 `1.4.0-beta.1`） | — |
| `-Push` | 成功后推送当前分支与 tag 到 origin | 关，仅本地 |
| `-Reorganize` | 发布后执行 `reorganize_publish.ps1` | 关 |
| `-CleanPublish` | 发布前清空 `publish` 目录（注意会删掉其中的 settings/history 等运行期文件） | 关 |
| `-AllowDirty` | 允许工作区有未提交改动 | 关 |
| `-SkipPublish` | 只打 tag 不发布（补打 tag 等特殊场景） | 关 |

脚本会对发布出的 `BBKSync.exe` 做三重版本校验：
`FileVersion` 与 `AssemblyVersion` 必须为 `主.次.补丁.0`，
`ProductVersion` 必须以所给版本号开头（正式版 `1.4.0+commit` / 预发布版 `1.4.0-beta.1+commit`）。
校验不过即判定发版失败并回滚本地 tag。

### 项目结构

```
LanFileSync/
├─ LanFileSync.csproj        项目文件（发布参数、MinVer 版本）
├─ App.xaml / App.xaml.cs    应用入口：单实例、软件渲染、全局异常→crash.log
├─ MainWindow.xaml(.cs)      主窗口：界面、设置绑定、服务启停、测试连接、托盘、密码空闲上锁
├─ MainWindow.Operation.cs   各类操作的编排（备份/更新/同步/升级/本机过滤）
├─ MainWindow.Tools.cs       其他小工具：备份递归扫描、剔除/重命名计划与执行（回收站）
├─ ThemeManager.cs           亮/暗主题切换
├─ *Window.xaml(.cs)         历史、IP 配置、暗色消息框子窗口
├─ Backup/                   BackupEngine（本机/共享备份）、BackupSyncEngine（远端备份）
├─ Sync/                     SyncEngine（BBK 增量/整体替换同步）
├─ Transfer/                 TransferEngine（文件同步：更新/拷贝模式）
├─ Net/                      TCP 服务端/客户端、帧连接、清单收发、SMB、源/目标侧
├─ Models/                   BackupOptions / SyncOptions / FileEntry
├─ Rules/                    UploadRules（Log/Config 跳过等规则）
├─ Themes/                   Light.xaml / Dark.xaml
└─ Util/                     常量、IP 解析、设置/历史存储、设备配置、压缩、
                             进程结束、托盘、脚本执行、路径解析等工具
```

### 通信协议简介

- 传输层：TCP，默认端口 25010；
- 帧格式：**4 字节小端整数长度 + UTF-8 JSON 正文**（最大帧 512 MB）；
- 文件内容在 JSON 协商后以**裸字节流**发送，接收侧先落 `.tmp` 再原子替换；
- 握手首帧携带角色：`probe`（探测/设备配置）、`pull`（备份/拉取源）、
  `push`（推送更新）、`transfer` / `transfer-pull`（文件同步）、
  `process-open` / `process-close`（进程管理）、`file-list`（文件列表）、`update`（程序升级）。

## 常见问题

### Q：为什么单击勾选框没反应？
**A：** 本程序所有勾选框都设计为**双击切换**，用于防误触，请双击勾选或取消。

### Q：提示「目标 IP 为本机地址，已跳过」？
**A：** 程序识别出输入的 IP 属于本机（回环或本机网卡地址），远端操作不允许以本机为目标。
若要操作本机数据，请直接使用「本机」备份来源或对应本地功能；请确认输入的是远端电脑 IP。

### Q：启动服务提示 10013 错误？
**A：** 多为安全软件/防火墙拦截或端口权限问题：
1. 将程序放到纯英文路径下运行；
2. 在 Windows 防火墙中允许 BBKSync 通过（或放行 25010 端口）；
3. 检查端口是否被其他程序占用。

### Q：测试连接失败但能 ping 通？
**A：** ping 只代表网络可达。请确认：
1. 远端已打开 BBKSync 并点击「启动服务」（程序一般会自动启动）；
2. 两端端口一致；
3. 远端防火墙放行了程序/端口（10060 多为防火墙静默丢包，10061 为端口没在监听）。

### Q：备份时提示「找不到路径」或「备份目标不能位于源文件夹内部」？
**A：** 检查 `Server.Root` 是否存在（JSON 中反斜杠需双写 `\\`），
并确保「备份到」目录与 BBK 源目录不同、且不在源目录里面。

### Q：如何修改或关闭密码保护？
**A：** 编辑 `settings.json` 的 `UpdatePassword`：改为新密码即可；**留空 `""` 即完全关闭**
BBK 更新、文件同步与进程管理的密码保护。默认密码是 `BBK123`，建议上线前修改。
解锁后切走标签页会立即重新加锁；停留在页面内连续 5 分钟无键盘/鼠标操作也会自动重新上锁。

### Q：如何自定义 PostgreSQL 备份脚本？
**A：** 程序目录下编辑 `PostgreSQL_Backup.bat`（首次运行自动生成模板）。
程序不会覆盖已有非空内容；脚本执行失败只警告，不会中断备份。

### Q：程序升级后远端没有更新成功？
**A：** 检查远端程序目录下的 `Update_BBKSync.bat` 与 `BBKSync_New.exe`：
- 脚本在程序启动时自动生成，若 exe 被放在无写入权限的目录会生成失败；
- 升级需要远端能在本目录删除/重命名 exe；
- 远端旧程序必须是本程序（靠脚本 taskkill 同名进程）。
- 两端必须同为 x64 版本。

### Q：日志在哪里？能导出吗？
**A：** 界面底部日志区实时显示（右下角悬浮「复制日志」「清空日志」，区域高度可拖拽），
点「复制日志」可粘贴到任何地方。程序崩溃时还会在程序目录写 `crash.log`。

### Q：设置文件在哪？程序目录不可写怎么办？
**A：** 默认在 `BBKSync.exe` 同目录的 `settings.json` / `history.json`；
目录不可写时自动改存 `%LocalAppData%\BBKFileSync\`。

### Q：如何完全卸载？
**A：**
1. 右键托盘图标 →「退出」彻底结束程序；
2. 删除程序文件夹；
3. 如曾开启开机自启，取消勾选即可清理注册表 `Run` 项（值名 `BBKSync`），也可手动删除；
4. 可一并删除 `%LocalAppData%\BBKFileSync`（若存在）。

### Q：窗口标题的版本号怎么来的？
**A：** 由 MinVer 根据 git tag 自动计算：正式发布打 `vX.Y.Z` tag 即显示对应版本；
tag 之后的开发构建显示带 `alpha` 与提交数的预览号，无需手工维护版本。
